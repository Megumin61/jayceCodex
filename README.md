# jayceCodex

这是一个面向 Jayce 的 **Codex 项目与会话中转仓库**。它用 GitHub 保存可追溯的长期记录，让本地 Codex 的聊天讨论和工作任务能够围绕同一个项目持续接力。

它不是自动同步全部聊天历史的“云端记忆”，而是一层用户可读、可编辑、可版本控制的持久上下文：原始会话负责留证，项目上下文负责接续，Git 负责在不同工作环境之间传递变化。

## 目录

```text
.
├─ AGENTS.md                         # Codex 进入仓库后遵循的协作约定
├─ CONVERSATIONS.md                  # 全仓会话总索引
├─ inbox/                            # 尚未归类的新导出
└─ projects/
   ├─ personal-thinking/             # “个人思考”项目
   │  ├─ README.md                   # 项目定位
   │  ├─ CONTEXT.md                  # 当前有效的长期上下文
   │  ├─ HANDOFF.md                  # 下一次会话的接续入口
   │  └─ conversations/              # 不改写的历史会话档案
   └─ _template/                     # 新项目模板
```

## 使用方式

1. 在一台设备开始工作前，先拉取仓库最新内容。
2. 在 Codex 中打开这个仓库，并说明本次属于哪个项目；未说明时不要自行混入其他项目。
3. Codex 先读 `AGENTS.md`，再读对应项目的 `CONTEXT.md` 和 `HANDOFF.md`。只有需要核对原话时才读取完整原始会话。
4. 一次讨论或工作完成后，把新记录归档到项目的 `conversations/`，并更新项目上下文、交接页和总索引。
5. 检查差异后提交并推送。另一种模式或另一台设备拉取后即可继续。

## 两类记录的分工

- **聊天讨论**：重点沉淀问题演进、判断、取舍、决策和仍未解决的问题。
- **工作任务**：重点沉淀目标、实际改动、验证证据、产物位置和下一步。
- **原始会话**：保留事实，不为了“更好读”而覆盖。
- **项目上下文**：只保留当前仍然有效、值得下一次直接加载的信息。

## 边界

- 不提交密码、Token、Cookie、私钥、个人隐私或未经授权的第三方数据。
- GitHub 是记录与运输层；Codex 新任务不会因为文件存在就自动读懂全部历史，所以必须维护短而新的 `CONTEXT.md` 与 `HANDOFF.md`。
- 大型二进制附件应存放在合适的外部位置；仓库只记录来源、摘要与可访问路径。
